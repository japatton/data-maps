# Brief: generate Cribl Stream 4.19 pipelines from an ECS data-map work order

You generate Cribl pipeline JSON from a work order, validate each one against a
live Cribl instance, and write the results to disk. Follow this brief exactly.

## Your inputs

Your prompt names one or more work orders. Each is at
`tools/pipelines/workorders/<name>.json`.

A work order name may be `<tech>` (whole technology) or `<tech>--<dataset>`
(one dataset of a large technology). Its `datasets[]` carries only the format
blocks that need a real parsing pipeline. Blocks that defer to Elastic are
already generated by a script — **do not produce those**, and do not add them.

Work-order structure:
- `technology`: `id, name, vendor, versions`
- `datasets[]`: `id, name, description, event_categories, route_direct, formats[]`
- `formats[]`: `format` (wire format), `parsing{mechanism,artifact,notes}`,
  `fields[]`, `recommendations`
- `fields[]` rows: `vendor` (raw field name or format specifier), `type`,
  `description`, `ecs` (target, or null), `status` (`mapped`|`unmapped`),
  `custom` (target when unmapped), `transform` (an instruction to implement),
  `notes`

## Scope

1. **DIRECT ROUTE ONLY.** Use `route_direct`. There is no cross-domain guard hop
   on this path — do not add serialization or framing for one.
2. **One pipeline per (dataset, format) pair.**
3. Every block you receive has mechanism `cribl-pipeline` or `cribl-pack`, so
   Cribl **is** the parser. Build a real parsing pipeline, not a pass-through.
   ★ For `cribl-pack`: **the `pack` FUNCTION has nothing to do with Cribl Pack
   artifacts** — it is a field-packing utility taking `unpackedFields`, and it
   cannot invoke a Pack. Separately, **no Packs are installed** (`GET /packs`
   returns 0 items), so a pack's internal pipelines and lookups do not exist to
   reference either. Build it yourself. The
   catalog's recommendation describes the work the pack *would* do; implement
   that shape natively with whitelisted functions. 24 such blocks remain, so
   expect this.
4. ★ **`recommendations.direct.cribl` is authoritative and outranks this brief.**
   It is the catalog author's instruction for that exact feed. If it says do
   something other than what the generic recipe below implies, follow it and say
   so in the pipeline `description`.

## Pipeline JSON schema (verified against the live instance)

```json
{
  "id": "dm_<tech>_<dataset>_<format>",
  "conf": {
    "output": "default",
    "description": "technology, dataset, format, and the parsing approach in one line",
    "functions": [
      { "id": "<function_id>", "filter": "true", "conf": {}, "description": "why this step exists" }
    ]
  }
}
```

`filter` is a JS expression string; use `"true"` when unconditional. `final` and
`disabled` are optional booleans. Pipeline `id` must match `[a-zA-Z0-9_]+` —
lowercase, every other character becomes `_`.

comment, distinct, dns_lookup, drop, drop_dimensions, dynamic_sampling, eval,
event_breaker, eventstats, externaldata, flatten, foldkeys, gen_stats, geoip,

local_search_datatype_parser, local_search_ruleset_runner,
local_search_schema_mapper, local_search_time_range_normalizer,
local_search_transformer, lookup, mask, mv_expand, mv_pull,
notification_policies, notifications, notify, numerify, otlp_logs, otlp_metrics,

rename, rollup_metrics, sampling, search_engine_export, send, serde, serialize,
sidlookup, snmp_trap_serialize, sort, store, suppress, tee, trim_timestamp,
union, unroll, window, xml_unroll

★ **There is no function called `parser`.** The UI's "Parser" is `serde`.
Inventing a function id is the most likely way to fail this task.

Verified conf shapes:
- `serde` extract: `{"mode":"extract","type":"json","srcField":"_raw"}` — `type`
  may be `json`, `csv`, `kvp`, `delim`, `elff`
- `rename`: `{"rename":[{"currentName":"srcip","newName":"source.ip"}]}`
- `grok`: `{"pattern":"%{COMMONAPACHELOG}","source":"_raw"}`
- `regex_extract`: `{"regex":"/pat(?<name>x)/","source":"_raw"}` — ★ the regex
  MUST be a JS-style literal wrapped in `/.../` delimiters. A bare pattern is
  rejected with `HTTP 400 Invalid regular expression ... Unexpected character`.
  Same for `regex_filter`. ★ But NOT universal: `xml_unroll`'s `unroll`/`inherit`
  properties take a BARE regex string with no slashes — their schema lacks the
  `"regexp": true` flag that `regex_extract`/`mask` carry, and the schema's own
  example has none. When in doubt, GET `/api/v1/functions/<id>` and look for
  that flag rather than assuming.
- `drop`: `{}` with the condition in `filter`
- `comment`: `{"comment":"text"}`
- `eval`: `{"add":[{"name":"event.dataset","value":"'tech_ds'"}],"remove":["gone"]}`
  — `value` is a JS expression, so a string literal needs inner quotes
- `auto_timestamp`: `{"srcField":"_raw","dstField":"_time"}`
- `mask`: for redaction; list EVERY field the parser materialized (`_raw` AND
  the parsed copy) or the parsed value leaks
- `flatten`, `json_unroll`, `mv_expand`: nested JSON and arrays
- `numerify`: numeric-looking strings to numbers

★ **`cef` is a SERIALIZER, NOT A PARSER.** Its live name is "CEF Serializer":
it builds a CEF string from an event. It cannot extract CEF input — an empty conf
fails with `Missing headers=[...]`, and adding a `mode` key is rejected as
`additionalProperties`. **To PARSE CEF or LEEF:** `regex_extract` with a `/.../`
literal for the pipe-delimited header fields, then either
`serde {"mode":"extract","type":"kvp"}` on the extension blob, or a second
`regex_extract` where an extension value can contain unescaped spaces (a naive kv
split truncates those). 49 syslog-cef and 30 syslog-leef blocks remain in this
fan-out, so this applies widely.

★ `rename` rejects any `currentName`/`newName` starting with `__` (double
underscore) with HTTP 400 — Cribl reserves that prefix. Use a single underscore
for temp fields.

**More verified shapes** (all confirmed HTTP 200 against the live instance, so you
may use these rather than declining the work):

- `suppress`: `` {"keyExpr":"`${__e['sys_id']}`","allow":1,"suppressPeriodSec":3600,"dropEventsMode":true} ``
  with filter `__e['sys_id'] !== undefined`, then an `eval` with
  `{"remove":["suppress"]}`. Use it for the sys_id / event-id de-duplication
  the maps ask for. The filter matters: without it every event missing the key
  shares the key `undefined` and all but the first are dropped. `suppress`
  stamps `suppress: 0` on each event it keeps, which the `eval` removes.
  ★ NOT `distinct`: it is an aggregation that emits only the `groupBy` fields
  and discards the rest of the event (lint: `distinct-drops-fields`).
- `mask`: `{"rules":[{"matchRegex":"/password=(\\S+)/","replaceExpr":"'REDACTED'"}],"fields":["_raw","message"]}`
  — ★ `replaceExpr` is a JS expression and **must not contain `=`**; a literal
  like `'password=REDACTED'` is rejected with `Unallowed assignment operator`.
  Use a bare `'REDACTED'`, or a hash: `C.Mask.md5(g1)` is accepted. List EVERY
  field holding the value, `_raw` included, or the parsed copy leaks.
- `lookup`: `{"file":"codes.csv","inFields":[{"eventField":"event.code","lookupField":"code"}],"outFields":[{"lookupField":"name","eventField":"event.action"}]}`
  — only use this when the map actually supplies lookup data; do not invent a CSV.
- `numerify`: `{}` is valid.
- `flatten`: `{"fields":["properties"],"prefix":"","delimiter":"."}`

★ After parsing `_raw` into fields, consider dropping `_raw` — otherwise a value
you masked or dropped downstream still sits in the raw copy and reaches Elastic.

★ **Functions that need a config object you are not allowed to create** — do not
reach for these, record the limitation as a gap instead:
- `join` needs `fieldConditions[]` plus a `stageId` pointing at a pre-existing
  stateful store; a bogus stageId crashes with `Cannot read properties of
  undefined (reading 'getRepo')`. Stateful cross-event correlation is therefore
  out of scope — tag events with a correlation id and let Elastic reassemble.
- `lookup` needs a real CSV on the instance. Only use it when the map supplies
  the data.

If unsure of a conf shape, GET an existing pipeline and copy its shape, or pick a
function whose shape you know. **Never guess a key name.**

## ★★ THE BIG ONE: awkward source field names cannot be renamed

**A path-based conf key only accepts a valid JS identifier path.** Every one of
these returns `HTTP 500 Failed to build property accessor`:

| Source name | Why it fails |
|---|---|
| `time-taken`, `c-ip`, `appliance-id` | hyphen parses as subtraction |
| `client address`, `Event Name` | space |
| `CAProperties:UserName` | colon |
| `%h`, `%{remote}p` | percent / brace |
| `Status.Call.0.Status` | numeric path segment, e.g. from `flatten`ing an array |

This hits **1,592 of 9,185 field rows across 76 of 97 technologies**, so assume
your work order contains some. The bracket form `['time-taken']` in
`currentName` fails too — do not try it.

★ **A DOTTED source key is the dangerous case: it passes validation and still
fails.** A genuinely flat key containing dots — Zeek's `id.orig_h`, `id.resp_p` —
is accepted by `rename.currentName` at HTTP 200, because a dot is legal in a
path. But the accessor then resolves it as NESTED (`id` -> `orig_h`), which is not
where the value lives, so the rename quietly matches nothing. Unlike a hyphen,
you get no error at all.

Handle it by QUOTING the name: `"currentName": "'id.orig_h'"` addresses the flat
key (verified on 4.19.0, 2026-09-22), exactly as `__e['id.orig_h']` does in an
`eval.add` value. Do not put an unquoted dotted source key in `rename` and assume
it worked.

Path-based keys (all affected): `rename.currentName`, `rename.newName`,
`eval.add[].name`, `eval.remove[]`, `auto_timestamp.srcField/dstField`.

**Verified working recipe** — map with `eval.add`, whose `value` is a free-form
JS expression where bracket access is legal:

```json
{"id":"eval","filter":"true","conf":{
  "add":[{"name":"http.response.time","value":"__e['time-taken']"},
         {"name":"source.address","value":"__e['client address']"}]}}
```

`name` is the ECS target, which is a valid path; `value` reads the awkward
source. To drop the source afterwards, `eval.remove` accepts a **wildcard glob**
(`"time-*"` is accepted; the literal `"time-taken"` is not), or use the `code`
function for full control:

```json
{"id":"code","filter":"true","conf":{"code":"__e['http.response.time'] = __e['time-taken']; delete __e['time-taken'];"}}
```

★ **Do NOT silently drop a field because `rename` rejected it.** Use `eval.add`
with bracket access. Dropping it passes validation while quietly losing the
mapping, which is worse than a visible failure. Only leave a row unmapped when
the map genuinely does not say what the source key is.

So: put all *clean* source names in one batched `rename`, and all *awkward* ones
in an `eval.add`. Most technologies need both.

★ **Numeric path segments have no removal path at all.** A key like
`Status.Call.0.Status` (what `flatten` makes of an array) is rejected by
`eval.remove` and by `rename`, and a glob will not always reach it. Read it with
`__e['Status.Call.0.Status']` in an `eval.add` value and simply LEAVE the original
in the event — a harmless duplicate field beats a rejected pipeline. Say so in the
pipeline's `conf.description` rather than pretending it was cleaned up.


## ★ Nine platform constraints found the hard way — respect all of them

1. **A field path containing `@` is rejected.** `rename.currentName/newName`,
   `eval.add[].name` and `auto_timestamp.srcField/dstField` all fail on
   `@timestamp` with `HTTP 500 Failed to build property accessor ... Unexpected
   token ILLEGAL`. **Never target `@timestamp`.** Write the event time to
   `_time`, Cribl's canonical time field, which the Elastic destination maps to
   `@timestamp` for you. Epoch seconds, e.g.
   `{"add":[{"name":"_time","value":"Date.parse(someField)/1000"}]}`.
   Reading it inside a value expression is fine: `__e["@timestamp"]`.
2. **`comment` has a 1000-character limit** — longer returns HTTP 400
   `maxLength`. Keep comments tight.
3. **`eval` takes a single EXPRESSION, not a script.** Arrow functions fail with
   `Expression cannot have any declarations`; IIFEs fail with `Expression cannot
   have nested scopes`. No `let`/`const`/`function`/`=>`. Replace `.find()` and
   loops with bounded ternary chains over fixed indices. If logic genuinely
   needs statements, use the `code` function instead.
4. **Read fields with `__e['name']`.** In an `eval` value or a filter, a bare
   identifier (`src_ip`) and a bare path (`event.action`) read the field and
   yield `undefined` when it is absent. They do not throw (re-verified on 4.19.0
   on 2026-09-22; this rule used to claim they did). But a bare dotted path
   addresses the NESTED object, and a field this pipeline wrote is a flat key
   (see the flat-key section below), so `event.action` misses a value that
   `__e['event.action']` finds. Bracket access is right in both cases. Inside a
   `code` function a bare identifier really does throw `ReferenceError`, because
   that is real JavaScript.
5. **`event.dataset` must not contain a hyphen** — it becomes the dataset
   component of an Elastic data stream name, which forbids `-`. Use
   `<tech_id>.<dataset_id>` with every hyphen replaced by `_`, e.g.
   `paloalto_ngfw.traffic`.
6. **A Syslog Source leaves the whole line in `_raw`.** Priority and header
   stay in `_raw`; the body is in `message` (probed on 4.19.0, see
   `docs/verification/2026-09-23-cribl-syslog-source-framing.md`). Sent with no
   application tag, a CEF line even loses `CEF` from `message`. So in a
   `syslog-*` pipeline: find a CEF/LEEF header anywhere in `_raw`
   (`/CEF:(?<v>\d+)\|.../`, never `/^CEF:/`); parse a body format from
   `__body`, set first by an `eval` of `__e['message'] !== undefined ?
   __e['message'] : __e['_raw']`; and if the regex reads the syslog header
   itself, start it `^(?:<\d{1,3}>)?`. Lint: `syslog-anchored-on-raw`,
   `syslog-serde-on-raw`.
7. **The `eval`/filter sandbox lacks some JS globals.** `parseInt`,
   `parseFloat`, `isNaN`, `isFinite`, `encodeURI`, `decodeURI`, `escape`,
   `atob`, `btoa`, `Symbol`, `BigInt`, `Buffer`, `Intl`, `Error`, `NaN` and
   `Infinity` are all `undefined` there (probed on 4.19.0): the expression
   silently yields nothing, and HTTP 200 on save. Use `Number.parseInt`,
   `Number.parseFloat`, `Number.isNaN(Number(x))`; `Date`, `Math`, `String`,
   `Number`, `JSON`, `RegExp`, `Map`, `Set` and `encodeURIComponent` work. A
   `code` function has the full set. When such an expression assigns `_time`,
   make every fallback branch keep `__e['_time']` - an expression that yields
   `undefined`, `null` or `NaN` there removes or nulls the event time. Lint:
   `eval-missing-global`.
8. **`regex_extract` into an existing field makes an array** unless its conf
   sets `"overwrite": true` (probed on 4.19.0: `severity` 6 plus a captured
   `'9'` became `[6, '9']`). A Syslog Source has already set `message`,
   `host`, `appname`, `procid`, `msgid`, `severity` and `facility`, so a
   `syslog-*` regex that captures any of those names - the CEF header's
   `severity` is the usual one - needs `overwrite`. `serde` overwrites on its
   own. Lint: `syslog-capture-collides`.
9. **Never assign `_time` straight from an expression.** One that fails - a
   missing field, an unparseable date, a throw - writes `null` or `NaN` over
   the event time (probed on 4.19.0: a throwing expression yields `null`). Put
   the expression in `__dm_time`, then in the same `eval`, next entry:
   `_time` = `__e['__dm_time'] !== undefined && __e['__dm_time'] !== null &&
   __e['__dm_time'] === __e['__dm_time'] ? __e['__dm_time'] : __e['_time']`
   (the `x === x` test rejects `NaN`). Entries of one `eval` run in order.
   That exact form translates to Painless; `__dm_*` scratch fields become
   `dm_tmp.*` in Elasticsearch and are removed at the end. Lint:
   `eval-time-unguarded`.

## Build each pipeline like this

1. `comment` naming technology, dataset, format, and the parsing approach
2. deserialize/parse per the wire format: `serde` for JSON/KV/CSV, `grok` or
   `regex_extract` for text, and for CEF/LEEF see the warning below — **not**
   the `cef` function
3. ONE `rename` batching every `status: mapped` row: `currentName` = the field
   name your parse step actually produced, `newName` = `ecs`, QUOTED when it
   contains a dot (`"'source.ip'"`)
4. `eval` implementing each row's `transform`, and routing `status: unmapped`
   rows with a `custom` value to that custom target
5. `eval remove` or `drop` for rows the notes or transform say to discard
6. set `_time` from the event's own timestamp field (constraint 1)
7. `eval` adding `event.dataset` (constraint 4)
8. the canonical re-nest `code` step, LAST: run
   `python3 tools/pipelines/flat_keys.py` and it is appended (and every dotted
   write and flat read quoted for you); `python3 -m datamaps.cribl_lint` fails a
   pipeline without it

★★★ **DOTTED TARGETS ARE FLAT KEYS, AND THE PIPELINE ENDS BY RE-NESTING THEM.**
An unquoted dotted `eval.add` name or `rename.newName` is written ONLY when its
parent object already exists. Otherwise `eval` writes nothing and `rename`
DELETES the source value. That holds for `source.ip` when there is no `source`,
and for two renames into the same new parent. It was verified on 4.19.0 and
4.14.0 through preview and through a real source-to-destination path
(`docs/verification/2026-09-22-cribl-field-semantics.md`). Every pipeline
committed before 2026-09-22 lost most of its mapped fields this way, and the
API accepted all of them with HTTP 200.

So, as Cribl's own `prep_for_ECS` pipeline does:
- quote every dotted target, `"name": "'event.action'"`, which writes a flat
  key and never loses anything;
- from then on, read it flat, `__e['event.action']`, and name it quoted in a
  later `rename.currentName`, `eval.remove`, `srcField` or `groupBy`. The
  exception is `mask.fields`: it is a wildcard pattern that matches the flat
  key when unquoted, and nothing when quoted;
- never guard on the parent (`__e['event'] && ...`): the object does not exist
  until the re-nest step builds it;
- end with the canonical re-nest step (`datamaps/renest.js`). It turns every
  flat dotted key into nested objects and merges into parents that already
  exist. Where a parent is a scalar (a vendor `user` string) it leaves the flat
  key in place, and the live gate reports that as a collision: rename or
  remove the vendor field first.

`tools/pipelines/flat_keys.py` applies all of this mechanically. The lint and the
live gate's behaviour check (a sentinel at every renamed field must survive) hold
you to it.

Computing derived fields from the ORIGINAL vendor names before the batched
`rename` is still the clearest order.

Skip a step the data does not call for. Do not pad with no-op functions. Prefer
one `rename` with many pairs over many `rename` functions.

**Redaction/masking:** where a recommendation names a concrete field and a
concrete pattern, implement it with `mask`. Where it recommends masking but
defines no algorithm or token scheme, do NOT invent one — record it as a gap.

**Where a field name is unguessable** (a map listing generic vendor mnemonics
rather than the literal keys an upstream decoder emits, or operator-chosen JSON
key names with no standard), do NOT guess. Leave it unmapped and say why in the
pipeline's `conf.description`. A documented gap is worth more than a wrong rename.

```
TOKEN=$(curl -s -X POST $CRIBL_URL/api/v1/auth/login -H 'Content-Type: application/json' -d "{\"username\":\"$CRIBL_USER\",\"password\":\"$CRIBL_PASSWORD\"}" | python3 -c 'import sys,json; print(json.load(sys.stdin)["token"])')

curl -s -X DELETE "$CRIBL_URL/api/v1/pipelines/<id>" -H "Authorization: Bearer $TOKEN" -o /dev/null -w 'HTTP %{http_code}\n'
```

`$CRIBL_URL`, `$CRIBL_USER` and `$CRIBL_PASSWORD` come from the operator's own
environment; they are never stored in a file in this repository.

HTTP 200 on create means the schema and every function conf are valid. On
non-200, READ the error body, fix the file, retry until it returns 200. Delete
every pipeline you create — leave none behind. **Never report success for
anything you did not see return 200.**
